# Dependency Visualizer CLI

Минимальный инструмент для сбора и анализа зависимостей пакетов в формате **Alpine APK** и построения графа зависимостей (BFS, без рекурсии).  
Реализовано в виде простого CLI‑приложения на Python. Репозиторий содержит реализацию трёх этапов задания.

---

## Кратко
Проект обеспечивает:
- CLI‑конфигурацию (аргументы командной строки);
- извлечение прямых зависимостей из `.apk` (через разбор `.PKGINFO`);
- построение транзитивного графа зависимостей алгоритмом BFS без рекурсии;
- тестовый режим: вместо скачивания пакетов используется локальный файл с графом (формат: `A: B C`);
- защита от циклов и ограничение глубины обхода.


---

### Этап 1 — Прототип и конфигурация
**Требования:**
- Параметры задаются через CLI (аргументы).
- Параметры: имя пакета, `--repo` (URL или путь), `--mode`, `--max-depth`.
- Вывод всех пользовательских параметров при старте (для проверки).
- Обработка ошибок параметров.

**Реализация:**
- Парсер аргументов через `argparse`.
- Поддерживаются опции:
  - `--package / -p` (обязательный)
  - `--repo / -r` (обязательный)
  - `--mode / -m` (выбор: `auto`, `file`, `dir`, `test`, `test2`; default `auto`)
  - `--max-depth / -d` (int, default 5). Отрицательная глубина — ошибка.
- При запуске отображаются все параметры.
- Проверки: существование файлов, корректность `max-depth`, наличие пакета в индексе (в основном режиме).

---

### Этап 2 — Сбор данных (Alpine APK)
**Требования:**
- Использовать формат Alpine (`.apk`) и `APKINDEX`.
- Извлечь прямые зависимости пакета по URL репозитория.
- Вывести прямые зависимости.

**Реализация:**
- Функция `download_index()` скачивает `APKINDEX.tar.gz` с официального зеркала (по умолчанию пример для v3.14/main/x86_64).
- `parse_index()` парсит `APKINDEX`, сопоставляя `pkgname` и `version` → формирует имя `pkgname-version.apk`.
- `fetch_package_info()` — при указании короткого имени находит полное имя через индекс и скачивает `.apk` в временную папку.
- `get_dependencies()` — открывает `.apk` (tar.gz), читает `.PKGINFO`, собирает все `depend = ...`.
- В обычном режиме команда печатает прямые зависимости запрошенного пакета.

---

### Этап 3 — Построение графа и операции (BFS)
**Требования:**
- Построить транзитивный граф зависимостей через BFS без рекурсии.
- Учитывать `--max-depth`.
- Обрабатывать циклы.
- Тестовый режим: загружать граф из файла (формат: `A: B C`).

**Реализация:**
- `build_graph_bfs()` использует `collections.deque`:
  - Очередь хранит пары `(pkg, depth)`.
  - `visited` — множество посещённых пакетов (предотвращает циклы).
  - Для каждого пакета извлекаются зависимости (из тестовой структуры или из `.apk`), заносятся в `graph` с полем `depth`.
  - Зависимости добавляются в очередь с `depth+1` (если `depth <= max_depth`).
- Тестовый режим (`--mode test`) — `load_test_repo()` читает текстовый файл вида:  
A: B, C  
B: D  
C: D, E  
D: B  
E:
  и использует его вместо скачивания реальных apk.
- После завершения выводится итоговый граф в виде вложенного списка (с отступом по глубине).
